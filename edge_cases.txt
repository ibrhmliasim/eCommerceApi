Edge cases для e-commerce (самое важное)

Вот где сервис слой реально окупается.

🔐 1. Брутфорс логина

Решение:

throttle + Redis
RateLimiter::hit($key);

Edge-case:

один email → много IP
один IP → много email

👉 учитывать оба

🧾 2. Soft deleted user

У тебя уже есть SoftDeletes.

Edge-case:

пользователь удалён → пытается логиниться
if ($user && $user->trashed()) {
    throw new AuthenticationException('Account deleted');
}
📧 3. Email не подтверждён

Критично для e-commerce:

нельзя давать доступ к заказам
🛒 4. Guest → User merge (очень важно)

Сценарий:

пользователь добавил товары в корзину без логина
потом логинится

👉 нужно:

перенести cart
$this->cartService->mergeGuestCart($user, $sessionId);
🔁 5. Multiple devices

С Sanctum:

несколько токенов
logout только текущего устройства или всех
💳 6. Fraud detection

Минимум:

логин с нового IP
смена страны

👉 можно:

отправлять email
требовать повторную авторизацию
🔒 7. Credential stuffing

Решение:

Redis + блокировка
🔑 8. Password reset race condition

Edge-case:

несколько reset запросов

👉 invalidate старые токены

5. Если ты уже используешь Sanctum

Тогда login должен быть НЕ через session, а через токены:

$token = $user->createToken('auth_token')->plainTextToken;

Ответ:

return [
    'user' => $user,
    'token' => $token,
];

Actions/ (опционально, если пойдешь глубже)
    Auth/
        RegisterUserAction.php
        LoginUserAction.php

        -----------------------------------------------

1. Юзер вводит email → POST /password/forgot
2. Laravel генерирует токен → сохраняет в password_reset_tokens таблицу
3. Отправляет письмо со ссылкой (токен внутри)
4. Юзер кликает ссылку → попадает на frontend форму
5. Вводит новый пароль → POST /password/reset (токен + email + новый пароль)
6. Laravel проверяет токен → обновляет пароль → удаляет токен
